# Fork policy

## Purpose

Alexi5000/awesome-llm-apps is an applied agent-engineering fork of [Shubhamsaboo/awesome-llm-apps](https://github.com/Shubhamsaboo/awesome-llm-apps). The fork preserves upstream credit and Apache-2.0 licensing while adding Alexi5000-specific documentation, quality gates, and review guidance for agent-building and automation practice.

## Maintenance boundary

The upstream repository remains authoritative for its original catalog content. This fork is authoritative for files that express its own purpose, contribution process, security/support paths, review standards, and automation. Do not present fork-only guidance as upstream policy.

When an improvement is generally useful to the upstream catalog and does not depend on fork-specific context, maintainers should consider proposing it upstream. When a change represents Alexi5000’s working conventions, operational reviews, or curated learning path, it belongs in this fork.

## Synchronization discipline

Before syncing upstream, review the incoming changes, preserve any fork-specific files, run the repository quality contract, and document meaningful conflicts or intentional deviations in the resulting pull request or commit. Do not overwrite upstream attribution, licenses, or contributor credit.

## Example readiness

Catalog entries are learning and reference artifacts. A contributor must not label an example production-ready without documenting its provider assumptions, credentials strategy, threat model, operational controls, evaluation approach, and deployment context. Review any external action, automation, browser integration, or data access path before executing it with real systems.
